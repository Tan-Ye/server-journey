# server-journey

前端转后端的学习历程仓库。主线目标：**用 Rust 从零构建一个具备生产形态的交易内核**（`projects/trade-core`），在真实并发压力下保证不超卖、不重复下单、回调幂等，并且可部署、可观测、可恢复。

- 周期：**12 周**（10 周内容 + 2 周缓冲）
- 预算：**21 h/周** —— 周一~周五 3h/天，周六 5h，周日 1h 复盘
- 技术栈：Rust · Axum · SQLx · PostgreSQL · Redis · Docker · Nginx · Prometheus
- 规则：**每天必须留下一个 commit 或一份笔记文件，否则不算完成**

完整路线、验收标准（DoD）、逐周计划、风险与应对见 [ROADMAP.md](ROADMAP.md)。

## DoD 速查

| # | 标准 | 验证方式 |
| --- | --- | --- |
| 1 | 不超卖 | 库存 = 100，1000 并发下单，成功恰好 100 笔，无负库存 |
| 2 | 下单幂等 | 同一 Idempotency-Key 重发 100 次，只产生 1 笔订单 |
| 3 | 回调幂等 | 同一支付回调重放 50 次，状态只流转一次 |
| 4 | 超时取消 | 未支付订单 30 分钟内自动取消并归还库存，重启不丢任务 |
| 5 | 契约完整 | 全部接口有 OpenAPI 文档，前端 TS 类型自动生成 |
| 6 | 可上线 | 一条命令部署到云服务器，HTTPS 可访问 |
| 7 | 可观测 | Prometheus 看到 QPS / P99 / 下单成功率 / 扣减冲突率 |
| 8 | 可恢复 | 完成一次数据库备份 + 恢复演练并记录耗时 |
| 9 | 有沉淀 | 12 篇周复盘 + 各阶段笔记 + 架构文档 + 压测报告 |
